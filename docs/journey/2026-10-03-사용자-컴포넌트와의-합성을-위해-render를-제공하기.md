# 2026-10-03 — 사용자 컴포넌트와의 합성을 위해 render를 제공하기

## 문제

Coral의 Part가 기본 HTML 요소만 렌더링하면, 사용자가 이미 운용하는 `<Text>`나 `<Box>` 같은 컴포넌트와 결합하기 어렵다. Progress와 Meter의 `Label`, `ValueText`, `Track`, `Indicator`를 구현하면서 이 Part들이 `render`를 지원해야 하는지 논의했다. 기존 [render 결정](./2026-09-07-render를-네이티브-tag의-계약에-따라-제공하기.md)은 확인된 합성 요구가 있을 때 지원을 열도록 했지만, 사용자 컴포넌트와 합성해야 한다는 구체적인 이유는 담고 있지 않았다.

## 접근 방식

기본 요소만 제공하면 Coral이 렌더링하는 태그와 속성의 범위가 분명하다. 반면 사용자가 `<Text>`나 `<Box>`를 쓰는 경우에는 별도 요소를 감싸거나 기존 컴포넌트의 사용을 포기해야 한다. `render`를 제공하면 Part가 계산한 속성과 상태를 사용자 컴포넌트에 결합하면서, 사용처의 컴포넌트 체계를 유지할 수 있다.

Progress와 Meter의 시각적 Part에는 이 합성 요구가 적용된다고 판단해 `render`를 지원하기로 했다. 이 논의는 특정 두 컴포넌트의 편의를 넘어, 다른 Coral 컴포넌트에서도 같은 요구를 고려할 근거가 된다. 다만 이전 결정에서 확인한 네이티브 태그의 의미와 동작을 교체할 수 있는지는 각 Part의 계약에 따라 판단해야 한다.

## 해결

Coral은 사용자가 운용하는 `<Text>`나 `<Box>` 같은 컴포넌트와 합성할 수 있도록, Progress와 Meter의 `Label`, `ValueText`, `Track`, `Indicator`에 `render`를 제공한다. 사용자 컴포넌트와의 합성은 `render` 지원을 판단할 때 실제 사용 요구로 인정한다. 이 결정은 기존 기록보다 나중에 확정되었으며, 앞으로 다른 컴포넌트의 Part에도 같은 합성 요구를 반영한다.

`render`의 적용 범위를 정할 때에는 Part의 핵심 의미나 동작이 네이티브 태그 자체에 의존하는지도 함께 판단한다. 따라서 이번 결정이 모든 Part의 태그 교체를 일괄적으로 허용한다는 뜻은 아니다.
