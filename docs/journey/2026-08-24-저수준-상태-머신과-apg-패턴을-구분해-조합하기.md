# 2026-08-24 — 저수준 상태 머신과 APG 패턴을 구분해 조합하기

## 문제

Bison은 접근성 규칙을 사용처의 조합에 맡기지 않기 위해 완성된 WAI-ARIA APG
패턴을 공개 단위로 제공하기로 했다. 그러나 Dialog를 설계하면서 열기, 닫기와
해제 같은 상태 전환은 Disclosure를 비롯한 여러 패턴과 패턴 밖의 UI에서도
반복된다는 점이 드러났다. 이 전환을 패턴마다 다시 구현하면 같은 행동이 서로
다르게 발전할 수 있고, 공통 수정도 여러 패키지에 반복해야 한다.

반대로 `openable`이나 `dismissable`을 그 자체로 Bison 패턴이라고 부르면 기존
원칙과 충돌한다. 이 개념에는 APG 패턴을 완성하는 Role, Parts의 관계, 키보드와
Focus 규칙 및 ARIA 계약이 없기 때문이다. 공통 상태 전이를 재사용하면서도 작은
기능 조각을 완성된 접근성 패턴처럼 오해하지 않게 하는 계층 구분이 필요했다.

## 접근 방식

첫 번째 방법은 각 APG 패턴이 열기와 닫기를 독립적으로 구현하는 것이었다. 패턴
하나만 보면 자급적이지만, 같은 상태와 Event를 중복해서 소유하고 패턴 사이의
행동이 어긋날 가능성이 생긴다.

두 번째 방법은 Openable과 Dismissable을 각각 공개 패턴으로 제공하고 사용자가
이를 조합하게 하는 것이었다. 재사용 범위는 넓지만, 사용자가 조합한 결과에
APG가 요구하는 의미 구조와 접근성 동작이 모두 있는지는 Bison이 보장할 수 없다.
이는 행동을 APG 패턴 단위로 제공하기로 한 결정으로 되돌아가는 방식이었다.

Dismissable을 상태 머신이 아니라 외부 Effect로만 보는 방법도 검토했다. 그러나
Dismiss는 현재 열린 상태에 들어오는 Event이고 그 결과 닫힌 상태로 전환되는
행동으로 설명할 수 있다. 별도로 논의하지 않은 Effect 계약을 추가하기보다 이미
정한 상태 머신의 언어로 표현하는 편이 자연스러웠다. 또한 Dismissable은 열기와
닫기 상태를 새로 정의하지 않고 Openable의 Props, State와 Event를 포함한 채
`dismiss`를 닫기 전환으로 연결할 수 있었다.

## 해결

Bison은 공개 APG 패턴과 패턴을 구성하는 저수준 상태 머신을 구분한다.
`@bison/core`는 공통 조합 단위로 Openable과 Dismissable 상태 머신 및 타입을
공개한다. Dismissable은 Openable의 계약을 확장하고 `dismiss` Event를 기존 닫기
전환에 연결한다.

이 저수준 머신은 APG 패턴이 아니다. `@bison/dialog` 같은 패턴 패키지가 필요한
머신을 조합하고 자신의 `connect`를 붙여 Role, Parts, HTML·ARIA와 키보드 계약을
완성했을 때 비로소 Bison의 패턴이 된다. 따라서 이전에 정한 “행동은 APG 패턴
단위로 제공한다”는 원칙은 유지하면서, Machine 계층에서는 공통 상태 전이를
재사용할 수 있다.

APG에 없는 Non-modal UI가 필요하면 컴포넌트 계층에서 Core의 저수준 머신을 직접
조합할 수 있다. 다만 그 결과를 Bison의 완성된 패턴으로 간주하지 않으며, Role과
접근성 계약을 정의하고 검증하는 책임도 해당 사용처가 가진다.
