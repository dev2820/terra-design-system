# 2026-07-28 — Elevation의 None과 음수 단계 경계 정하기

## 문제

Elevation 척도를 정의하려면 높이가 없는 상태를 단계로 제공할지, 기준면보다
들어간 상태까지 같은 척도에 포함할지 정해야 했다. `Elevation 0`을 제공하면
숫자 척도는 연속적으로 보이지만, 실제 토큰으로 구현하는 제품은 0에도 그림자나
다른 값을 할당해야 한다. 그러면 높이가 없다는 기준에 불필요한 표현이나 의미가
붙을 수 있었다.

음수 단계도 비슷한 문제가 있었다. 기준면보다 들어가 보이는 표현은 개념적으로
음의 높이라고 설명할 수 있지만, 실제로는 바깥 그림자의 크기를 줄이는 것보다
안쪽 그림자, 테두리와 배경 차이처럼 다른 표현 방식을 요구할 수 있다. 이를
공통 Elevation 척도에 포함하면 양수 단계와 같은 기준으로 비교할 수 있는지
불명확해질 수 있었다.

## 접근 방식

먼저 `elevation.0`을 공개 토큰으로 제공하는 방식을 검토했다. 0이라는 이름은
기준점으로 이해하기 쉽지만, 제품이 토큰값을 채우거나 재매핑할 때 0에도 구체적인
값을 정해야 한다. 0을 면에 닿아 있는 상태의 약한 그림자로 정의하는 대안도
검토했으나, 이 경우 높이가 없는 상태와 약한 시각 효과를 구분하기 위해 다시
별도의 `None`이 필요해진다. Terra에서는 0에 그러한 의미를 부여할 근거가 없었고,
의미를 열어두면 제품마다 0이 다른 상태를 나타낼 가능성이 있었다.

음수 Elevation을 `Elevation -1`처럼 숫자 척도에 넣는 방식도 검토했다. 이 방식은
`-1 < None < 1`이라는 순서를 만들 수 있지만, 들어간 표현이 양수 Elevation과
동일한 종류의 값으로 구현된다고 보장하기 어렵다. 반대로 음수 표현을 전혀
허용하지 않으면 입력 영역이나 오목한 면이 필요한 제품이 Terra를 우회해야 할 수
있으므로, 공통 제공 여부와 제품의 확장 가능성을 분리할 필요가 있었다.

## 해결

Terra는 `None`을 Elevation이 적용되지 않은 개념적 기준으로 정의하고, 별도의
단계값이나 토큰으로 제공하지 않기로 했다. 구현에서는 Elevation을 적용하지 않는
것으로 `None`을 표현하며, Foundation은 여기에 그림자나 다른 의미를 부여하지
않는다.

공통 Elevation 척도는 기준면보다 높은 양수 단계만 다룬다. 음수 Elevation은
기본 단계로 제공하지 않지만, 기준면보다 들어간 표현이 필요한 제품이 별도의
확장으로 정의하는 것은 막지 않는다. 그 확장은 Terra의 공통 양수 척도와 같은
값이나 순서로 보장되지 않으며, 구체적인 이름과 표현 방법도 해당 제품이 정한다.
