# 2026-08-10 — Space를 일곱 개의 절대적인 숫자 단계로 시작하기

## 문제

Spacing Foundation에 제공할 단계의 이름, 개수와 관계를 정해야 했다. 간격은
작은 아이콘과 텍스트 사이부터 컴포넌트 그룹과 화면의 큰 영역 사이까지 넓은
범위에서 사용된다. 단계가 적으면 이 범위를 표현하기 부족할 수 있고, 단계가
많으면 실제 필요가 확인되기 전에 비슷한 선택지를 늘릴 수 있다.

또한 숫자가 실제 값이나 배율을 뜻하는지, 같은 단계가 위치에 따라 달라지는지,
간격이 없는 상태와 음수 간격을 공통 척도에 포함할지도 함께 결정할 필요가
있었다.

## 접근 방식

T-shirt 크기 이름은 읽기 쉽지만 중간 단계를 추가하거나 범위를 넓힐수록
이름이 어색해진다. 용도 이름은 어떤 관계에 사용할지를 알려주지만 Space를
특정 컴포넌트나 배치에 결합한다. 숫자 이름은 값을 직접 설명하지 않지만
순서와 확장을 중립적으로 표현할 수 있다.

Atlassian, Carbon, Spectrum과 Fluent의 공식 체계를 비교했다. Atlassian,
Carbon과 Spectrum은 숫자 기반 척도를 제공하지만, 숫자에 8px 기준의 배율이나
실제 값의 단계가 연결되어 있다. Carbon은 일곱 개의 양수 간격 단계를, Spectrum과
Atlassian은 더 넓은 범위의 단계를 제공한다. Terra는 특정 값이나 비율을
Foundation에서 고정하지 않으므로, 이 수치를 그대로 가져오는 대신 일반적인
제품 UI의 작은 간격부터 넓은 구조까지 시작점으로 포괄할 단계 수를 선택해야
했다.

## 해결

Terra는 `space.none`과 `space.1`부터 `space.7`까지를 기본 Space 단계로
제공한다. `space.none`은 간격을 두지 않는 실제 선택지이며, 숫자 단계는
절대적인 간격으로 해석한다. 같은 단계는 적용 위치와 방향에 관계없이 같은
간격을 나타낸다.

숫자는 실제 값, 일정한 값 차이나 배율, 특정 용도를 뜻하지 않고 순서만
나타낸다. 실제 값은 Token Set이 정하며, 각 단계가 순서에 맞게 시각적으로
구분되어야 한다. Terra는 음수 Space를 공통 단계로 제공하지 않는다. 음수
간격은 빈 공간이 아니라 겹침과 위치 이동을 만드는 별도의 표현이기 때문이다.

기본 범위가 부족하면 `space.8`, `space.9`처럼 더 큰 숫자를 뒤에 추가한다.
기존 단계 사이에 새 단계를 삽입하지 않음으로써 기존 단계의 순서와 의미를
보존한다.
