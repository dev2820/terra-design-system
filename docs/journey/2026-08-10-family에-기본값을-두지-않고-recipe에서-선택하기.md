# 2026-08-10 — Family에 기본값을 두지 않고 Recipe에서 선택하기

## 문제

Typography Foundation에서 모든 Token Set이 `family.base`를 정의하게 할지,
`Sans`, `Mono`처럼 글꼴의 종류를 선택지로 제공할지 결정해야 했다. 기본 Family
하나를 요구하면 별도 지정이 없는 문자에 사용할 계열이 분명해지지만, 여러
계열을 동등하게 사용하는 디자인 시스템에서도 하나를 암묵적인 기준으로 삼게
된다.

또한 `Base`, `Mono`, `Display`를 같은 목록에 놓으면 시스템에서의 역할, 글꼴의
형태와 사용 목적이라는 서로 다른 명명 기준이 섞인다. Terra가 추가 Family의
이름과 개수를 미리 정하면 하나의 글꼴만 필요한 제품도 사용하지 않을 선택지를
정의해야 하고, Serif를 중심으로 하는 제품처럼 미리 예상하지 않은 구성을
제약할 수 있었다.

## 접근 방식

`family.base`를 필수로 두는 방식은 가장 간단하며 전역 기본 글꼴을 예측하기
쉽다. 그러나 어떤 Family가 기본인지는 글꼴 자체의 속성이 아니라 완성된 디자인
시스템의 선택이다. Foundation이 이 역할을 소유하면 Family의 조합과 적용을
Recipe에 맡긴다는 구조와도 겹친다.

`family.sans`, `family.serif`, `family.mono`처럼 시각적 분류를 공통 목록으로
제공하는 방식도 검토했다. 명명 기준은 통일할 수 있지만 모든 Token Set에 같은
종류의 글꼴이 필요하다고 가정하고, 코드나 브랜드 제목처럼 실제 사용 목적과의
연결은 다시 별도로 정의해야 한다.

Family를 순서 없는 선택지 집합으로 두면 Token Set은 실제로 필요한 계열만
정의할 수 있다. 대신 암묵적인 기본값이 없으므로 완성된 디자인 시스템의
Recipe가 각 문자 표현에 사용할 Family를 선택해야 한다. 이는 Foundation은
선택지를 제공하고 Recipe가 조합과 용도를 정한다는 Terra의 책임 구조에
부합한다고 판단했다.

## 해결

Terra는 `family.base`나 고정된 Family 목록을 제공하지 않는다. 각 Token Set은
하나 이상의 Family를 정의하되, 그 이름과 개수는 자신의 필요에 맞게 정한다.
Family 사이에는 Foundation 차원의 순서와 기본값이 없다.

실제로 사용할 Family는 Recipe가 명시적으로 선택한다. 따라서 하나의 글꼴만
필요한 시스템은 하나의 Family만 정의할 수 있고, 코드나 표현적인 제목을 위해
여러 계열이 필요한 시스템은 필요한 만큼 확장할 수 있다. 이 선택은 기본값의
편의보다 파생 디자인 시스템이 자신의 문자 체계를 명시적으로 구성할 자유를
우선한다.
