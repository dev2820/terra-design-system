# 2026-11-17 — 문자 탐색의 검색 문자열을 500ms 후 초기화하기

## 문제

Select의 문자 탐색은 입력한 문자로 시작하는 항목을 찾는다. 여러 문자를 이어서
입력하면 전체 문자열을 접두어로 사용하므로, 연속 입력을 같은 검색으로 묶을
시간 기준이 필요했다. 검색 문자열을 계속 유지하면 잠시 뒤 새로 입력한 문자까지
이전 검색에 붙게 된다.

현재 구현에는 마지막 문자 입력 후 검색 문자열을 비우는 500ms 타이머가 있었다.
키보드 코드를 검토하면서 이 타이머가 W3C에서 정한 동작인지, 사용 편의를 위해
Coral이 선택한 정책인지 확인할 필요가 생겼다. 이 구분은 이후 입력 간격을
검토할 때 적용할 판단 기준이 된다.

## 접근 방식

[WAI-ARIA APG Listbox 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/#keyboardinteraction)은
문자 탐색을 권장한다. 문자 하나를 입력하면 해당 문자로 시작하는 다음 항목으로,
여러 문자를 빠르게 연속 입력하면 전체 문자열로 시작하는 항목으로 이동하도록
안내한다. ‘빠르게 연속해서’의 구체적인 시간 간격과 타이머 구현 방법은
지정하지 않는다.

[APG Select-Only Combobox 예제](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/)도
빠른 연속 입력을 전체 문자열로 탐색하고, 같은 문자를 반복하면 해당 문자로
시작하는 항목들을 순회하는 동작을 설명한다.
[Menu·Menubar 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/#keyboardinteraction)은
입력한 문자로 시작하는 다음 항목으로 이동하는 동작을 선택 사항으로 안내한다.

이 근거를 확인한 뒤, 연속 입력을 구분하는 구체적인 간격은 Coral에서 정할 수
있다고 판단했다. 사용자는 500ms가 프로젝트의 구현 정책이라는 설명을 확인하고
현재 방식을 유지하기로 했다. Select와 같은 간격을 사용하는 Menu·Menubar의
검색 문자열 초기화에도 이 정책이 적용된다.

## 해결

문자 탐색의 검색 문자열은 마지막 문자 입력으로부터 500ms가 지나면 초기화한다.
추가 문자가 들어오면 기존 타이머를 취소하고 문자열에 문자를 이어 붙인 뒤
타이머를 다시 시작한다. 이 간격 안의 입력은 하나의 접두어 탐색으로 처리하고,
초기화 후의 입력은 새 탐색으로 처리한다.

항목 탐색은 각 키 입력 시 즉시 수행한다. 500ms 디바운스는 검색 문자열을
초기화하는 작업에 적용한다. 같은 문자의 반복 입력에 따른 항목 순회도 유지한다.

500ms는 Coral이 채택한 상호작용 정책값으로 기록한다. APG의 연속 문자 탐색
안내를 구현하는 기준이며, 구체적인 간격의 변경 여부는 프로젝트 정책으로
판단할 수 있다. 세부 키보드 계약은
[Select 문서](../../packages/coral/src/select/README.md)에 둔다.
