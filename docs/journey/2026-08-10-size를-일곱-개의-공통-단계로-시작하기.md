# 2026-08-10 — Size를 일곱 개의 공통 단계로 시작하기

## 문제

Typography Foundation이 기본으로 요구할 Size 단계의 수를 정해야 했다. 작은
보조 문자부터 큰 제목까지 여러 크기가 필요하지만, Foundation에 단계를 하나
추가할 때마다 이를 따르는 모든 Token Set은 새로운 값을 정하고 단계 사이의
차이를 검증해야 한다.

단계가 적으면 일반적인 제품의 문자 위계를 구성하기 전에 곧바로 확장해야 할 수
있다. 반대로 8개나 9개처럼 더 많은 단계를 기본으로 요구하면 가벼운 제품도
사용하지 않을 크기까지 먼저 정의해야 한다. 몇 개의 단계가 일반적인 범위를
포괄하면서도 파생 디자인 시스템의 시작 비용을 과도하게 높이지 않는지 판단할
필요가 있었다.

## 접근 방식

다른 디자인 시스템의 공식 Typography 체계를 비교했지만 하나의 표준 단계 수는
없었다. [Primer](https://primer.style/product/primitives/typography/)는 여섯 개의
기본 크기를 제공하고, [USWDS](https://designsystem.digital.gov/design-tokens/typesetting/font-size/)는
더 넓은 시스템 척도 중 아홉 개를 기본 테마에 노출한다. Material 3와 Fluent 2는
여러 의미 기반 스타일이 같은 크기를 공유하고, Carbon은 제품 UI뿐 아니라
표현적인 콘텐츠까지 다루기 위해 더 넓은 척도를 제공한다.

이 비교에서 일곱이라는 수가 보편적인 정답이라는 근거는 찾지 못했다. 대신 제품
UI에 집중한 비교적 작은 척도도 실제 시스템을 구성할 수 있고, 시스템의 범위가
넓어질수록 단계도 늘어난다는 점을 확인했다. Terra는 완성된 제품 스타일을 모두
제공하지 않고 필요에 따라 확장하는 Foundation이므로, 일반적인 범위를 감당할
수 있는 작은 공통 집합으로 시작하는 편이 적합했다.

여섯 단계보다 선택지를 하나 더 제공하면 보조 문자, 본문과 제목 범위에서 여러
Recipe를 구성할 여지를 확보할 수 있다. 여덟 단계 이상이 필요한 제품은 공통
요구를 늘리는 대신 기존 순서를 이어 확장할 수 있으므로, 확인되지 않은 크기를
모든 Token Set에 미리 요구할 이유가 없었다.

## 해결

Terra는 `Size 1`부터 `Size 7`까지 일곱 개의 Size를 공통 단계로 제공한다. 모든
Token Set은 일곱 단계의 값을 정의하지만, 개별 Recipe가 이를 모두 사용할 필요는
없다.

일곱 단계는 Typography가 가질 수 있는 최대 범위가 아니라 파생 디자인 시스템이
공통으로 갖추는 시작점이다. 더 많은 크기가 실제로 필요하면 `Size 8`, `Size 9`
처럼 기존 순서를 이어서 확장한다. 이를 통해 일반적인 제품에 필요한 선택지를
제공하면서도 작은 시스템이 불필요한 값을 먼저 결정하는 부담을 제한한다.
