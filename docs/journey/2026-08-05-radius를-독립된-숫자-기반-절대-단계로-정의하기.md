# 2026-08-05 — Radius를 독립된 숫자 기반 절대 단계로 정의하기

## 문제

Radius의 이름과 값 해석 방식을 정해야 했다. Radius를 Button이나 Card처럼
사용처에 따라 이름 붙이면 의미를 쉽게 전달할 수 있지만, Radius가 특정
컴포넌트의 용도와 결합하고 제품의 변칙적인 형태를 수용하기 어려워진다.
또한 같은 단계가 요소 크기에 따라 달라지는 상대값인지, 어디서나 같은 둥글기를
나타내는 절대값인지도 결정해야 했다.

## 접근 방식

용도나 형태에 따른 이름은 의도가 분명하지만, 새로운 컴포넌트가 생길 때마다
토큰이 늘어나고 하나의 컴포넌트에 여러 Radius가 필요한 상황을 설명하기
어렵다. T-shirt 크기 이름은 읽기 쉽지만 단계 사이에 값을 추가하거나 범위를
확장할수록 이름이 어색해진다.

숫자 이름은 실제 둥글기의 정도를 직접 설명하지 않지만 특정 용도에 종속되지
않고, Elevation처럼 순서가 있는 다른 Foundation과 일관된 구조를 제공한다.
절대 방식은 같은 단계의 결과를 예측하기 쉽고, 상대 방식은 요소 크기에 따라
결과가 달라져 중첩된 형태와 단계의 비교가 어려워진다.

다만 원이나 Capsule을 만들기 위한 `Full`은 요소의 크기에 따라 실제 Radius가
달라져야 하므로 일반적인 절대 숫자 단계와 같은 방식으로 해석할 수 없었다.

## 해결

Radius는 요소의 모서리가 둥근 정도만 나타내는 독립된 기하학 축으로 정의한다.
특정 컴포넌트, 상태나 중요도를 Radius 이름에 포함하지 않는다.

기본 단계는 다음과 같이 숫자로 구분한다.

```text
None < Radius 1 < Radius 2 < Radius 3 < Full
```

`Radius 1`부터 `Radius 3`까지는 절대적인 단계로 해석하며, 숫자는 실제 값이나
배율이 아니라 둥글기의 순서만 나타낸다. 단계 사이의 일정한 값 차이나 배율은
강제하지 않고, 각 단계가 시각적으로 구분되는지만 보장한다.

`None`은 둥글기가 없는 실제 선택지로 제공한다. `Full`은 요소가 허용하는
최대한의 둥글기를 적용하는 특수한 끝점으로 두며, 정사각형에서는 원을,
직사각형에서는 Capsule을 만들 수 있다. Radius를 어느 요소와 모서리에
적용할지, 중첩된 Radius를 어떻게 조합할지는 Recipe가 결정한다.

이 구조는 Radius를 제품의 구체적인 용도에 고정하지 않으면서도 Elevation과
일관된 숫자 체계와 확장 가능한 단계를 제공한다.
