# 2026-08-10 — Spacing을 구현 방식과 독립된 관계의 Foundation으로 다루기

## 문제

요소 사이의 빈 공간은 코드에서 Margin, Padding, Gap처럼 서로 다른 속성으로
구현된다. 이 구현 방식을 기준으로 간격 체계를 나누면 같은 거리와 관계가
화면마다 다른 토큰과 규칙으로 표현될 수 있다. 또한 가로와 세로에 별도 척도를
두면, 방향이 달라졌다는 이유만으로 같은 관계에 다른 값을 선택해야 할 수 있다.

Terra는 빈 공간이 구현 속성 자체보다 요소가 얼마나 가까이 속하는지를 보여주는
표현이라고 보고, Spacing Foundation이 어느 범위까지 공통으로 다룰지 정할
필요가 있었다.

## 접근 방식

Margin, Padding과 Gap을 별도 체계로 두면 각 구현 속성에 맞는 세밀한 규칙을
만들 수 있다. 그러나 컨테이너 내부 여백, 형제 요소 사이의 간격, 화면 가장자리
여백이 모두 빈 공간을 통해 관계를 드러낸다는 공통점을 놓치게 된다.

가로와 세로에 다른 척도를 두는 방식도 검토했다. 방향별 최적화에는 유리하지만,
세로 목록을 가로 배치로 바꿀 때 관계의 의미와 사용 가능한 값이 함께 달라지는
문제가 있다. 반대로 하나의 척도를 사용하면 구현 방향과 무관하게 먼저 요소의
관계를 판단할 수 있다.

## 해결

Spacing은 요소 사이, 컨테이너와 콘텐츠 사이, 화면 가장자리와 콘텐츠 사이의
모든 빈 공간을 공통으로 다룬다. 가까운 요소는 같은 맥락에, 더 떨어진 요소는
다른 단위나 그룹에 속한 것으로 인식되도록 관계를 드러내는 것이 Spacing의
역할이다.

Margin, Padding, Gap은 Spacing을 구현하는 방법일 뿐 Foundation의 별도 범주가
아니다. 가로와 세로도 같은 Space 척도를 사용한다. Spacing은 새로운 Surface나
Boundary를 만들지 않으며, 어떤 구현 속성과 위치에 적용할지는 Foundation이
정하지 않는다.
