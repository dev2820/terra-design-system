# 2026-08-15 — 행동을 ARIA APG 패턴 단위로 제공하기

## 문제

Bison이 행동을 제공하는 단위를 정해야 했다. Focus 이동, 선택, 펼침과 닫힘,
외부 상호작용 같은 작은 기능을 각각 제공하면 사용자가 필요한 기능만 조합해
다양한 UI를 만들 수 있다. 그러나 Accordion이나 Tabs처럼 하나의 UI Pattern이
접근 가능하게 동작하려면 Parts의 의미와 관계, 상태 전환, 키보드 조작과 Focus
규칙이 함께 성립해야 한다.

기능 단위의 자유로운 조합은 일부 규칙을 빠뜨리거나 서로 맞지 않는 기능을
연결해 ARIA Authoring Practices Guide가 설명하는 Pattern과 다른 결과를 만들 수
있다. 접근성을 사용처의 조합 능력에 맡기지 않으면서도 Bison이 어디까지 행동을
소유할지 결정할 필요가 있었다.

## 접근 방식

기능 단위 방식에서는 Disclosure, Roving Focus나 Outside Interaction 같은
행동을 작은 Primitive로 나누고 사용자가 이를 조합한다. 재사용성과 표현의
자유는 높지만, 완성된 Pattern의 상태와 입력 규칙을 구성하고 검증하는 책임도
사용자에게 넘어간다. 기능 하나가 올바르게 구현되어도 조합된 결과가 올바른
Accordion이나 Tabs라는 보장은 없다.

Pattern 단위 방식에서는 Accordion처럼 ARIA APG에 정의된 Pattern 하나를 완성된
행동 계약으로 제공한다. 작은 기능을 임의로 조합하는 자유는 줄지만, Pattern에
필요한 Parts와 관계, 가능한 상태, 입력에 따른 전환, 키보드와 Focus 규칙을
하나의 단위에서 정의하고 테스트할 수 있다. 이는 접근성을 사후에 조립하는
선택지가 아니라 기본 동작으로 제공하려는 Terra의 방향에도 부합했다.

## 해결

Bison은 행동을 작은 기능 조각이 아니라 ARIA APG Pattern 단위로 제공한다. 각
Pattern은 필요한 Parts와 그 의미 및 관계, 상태와 전환, 키보드·포인터·터치 및
외부 상호작용에 대한 반응, Focus와 Selection 규칙, 상태에 따른 HTML과 ARIA
속성을 함께 소유한다.

따라서 `createAccordion`은 Accordion을 이루는 행동 계약 전체를 제공하며,
사용자가 개별 기능을 조합해 Accordion의 접근성 규칙을 다시 완성하도록 하지
않는다. Bison의 테스트도 내부 상태 머신의 형태보다 Pattern 전체에서 같은
입력과 상태가 약속된 결과를 만드는지를 검증한다. 이 선택은 임의 조합의 범위를
줄이는 대신 Bison을 통해 만든 Pattern의 행동과 접근성을 예측 가능하게 한다.
