# 2026-08-29 — Bison의 ID 참조 관계를 강한 계약으로 제공하기

## 문제

Bison은 상태와 행동에서 파생된 HTML과 ARIA 속성을 Part별 props 함수로
제공하고, 사용하는 측이 그 결과를 실제 요소에 적용한다. Disclosure는 Trigger와
Content의 펼쳐짐 상태를 `aria-expanded`로 전달해야 하지만, APG에서 Trigger의
`aria-controls`는 선택 사항이다. 따라서 Disclosure의 `id`와 ID 참조 관계를 APG의
최소 요구처럼 선택적으로 제공할지, Bison이 항상 완성된 관계를 만들도록 필수
계약으로 제공할지 결정해야 했다.

`id`를 필수로 두더라도 Bison이 최종 DOM을 소유하는 것은 아니다. 사용하는 측이
Trigger props를 누락하거나 Content props를 다른 요소에 적용하면 참조 관계는
깨질 수 있다. 그렇다면 Bison이 어디까지 보장하는지와, 완전히 강제할 수 없는
계약을 강하게 제공하는 것이 의미가 있는지도 함께 정리할 필요가 있었다.

## 접근 방식

첫 번째 방식은 `id`를 선택적으로 받고, 값이 있을 때만 Content에 ID를 부여하고
Trigger의 `aria-controls`를 연결하는 것이었다. 이 방식은 APG가 허용하는 최소
계약을 그대로 표현하고 사용하는 측의 ID 준비 부담을 줄인다. 반면 Bison이 이미
Trigger와 Content를 하나의 패턴으로 정의했음에도 두 Part의 명시적인 참조 관계가
인스턴스마다 달라진다. 사용하는 측이 매번 선택하고 검증해야 하므로 다중 Part
패턴의 계약도 예측하기 어려워진다.

두 번째 방식은 고유하고 안정적인 `id`를 필수로 받고, Bison이 Content의 ID와
Trigger의 `aria-controls`를 항상 같이 생성하는 것이었다. 이는 APG보다 강한 계약이며
사용하는 측에 ID의 고유성, SSR 전후의 안정성과 파생 ID와의 충돌을 관리할 책임을
요구한다. Content를 지연 Mount하거나 이미 가진 ID를 연결해야 하는 조합에서도
이 계약을 보존해야 한다. 대신 Bison이 제공하는 모든 Disclosure가 같은 관계를 갖고,
사용하는 측이 임의로 ID 참조를 조립할 필요가 없다.

Zag의 Collapsible도 필수 base ID를 기준으로 Part ID를 생성하고, Trigger의
`aria-controls`와 Content의 ID를 항상 연결한다. Part별 ID를 바꾸기 위한 선택적
`ids`도 제공한다. Zag는 접근성 관계 외에도 DOM 요소 조회와 크기 측정 등에 ID를
사용하므로 Bison과 모든 조건이 같지는 않다. 그러나 Framework에 독립적인 패턴이
자신이 소유한 Part의 ID 관계를 완성된 계약으로 제공하는 선례로 참고했다.

강한 props 계약을 선택해도 사용하는 측의 잘못된 적용을 원천적으로 막을 수는 없다.
그러나 이 한계는 선택적인 계약에도 동일하다. Bison이 자신의 반환값을 일관되게
만드는 일과 사용하는 측이 이를 올바른 DOM에 적용하는 일을 다른 책임으로 구분하면,
최종 DOM을 완전히 강제하지 못한다는 이유로 Bison 자체의 계약을 약하게 만들 필요는
없다고 판단했다.

## 해결

Bison은 자신이 정의한 다중 Part 패턴의 ID 참조 관계를 완성된 props 계약으로
제공한다. Disclosure는 `id`를 필수로 받고, Bison은 그 값을 기준으로 Content의
ID와 Trigger의 `aria-controls`를 항상 서로 일치하게 제공한다. APG가
`aria-controls`를 선택 사항으로 두더라도, Bison에서는 패턴에 따른 예측 가능한
관계를 제공하기 위해 더 강한 계약을 적용한다.

Bison이 보장하는 범위는 반환하는 props 사이의 상태와 ID 참조가 내부적으로
일관된다는 것이다. 사용하는 측은 고유하고 안정적인 `id`를 제공하고,
`getTriggerProps()`와 `getContentProps()`를 각각 올바른 Part에 적용해야 한다.
반환된 props를 누락하거나 다른 요소에 적용하면 Bison이 의도한 접근성 계약이
완성되지 않으며, 그 위험과 사용 조건을 문서에 명확히 알린다.
