# Coral Agent Guidelines

작업하기 전에 이 디렉터리의 `README.md`와 `TODO.md`를 읽고, 저장소 루트의
`AGENTS.md`도 함께 적용한다.

## 핵심 원칙

### 1. 네이티브 HTML을 먼저 사용한다

적용 가능한 HTML과 WAI-ARIA 명세를 지키고 WAI-ARIA APG 패턴을 구현 근거로
사용한다. 네이티브 요소가 의미, 키보드와 Form 동작을 제공하면 이를 유지한다.
ARIA로 네이티브 의미를 불필요하게 다시 만들지 않는다.

APG 항목이 있다는 이유만으로 Coral 컴포넌트를 추가하지 않는다. 반복해서
사용할 구조나 행동을 Coral이 더 안전하게 제공할 수 있는지 먼저 확인한다.

### 2. 컴포넌트가 완성할 계약을 먼저 정의한다

새 컴포넌트를 구현하기 전에 다음을 정한다.

- 해결하는 사용자 문제와 지원 범위
- 필요한 HTML 요소와 Parts의 의미 및 관계
- 필요한 경우에만 상태, 초기 상태와 상태 변화
- 키보드, 포인터, 터치와 외부 상호작용의 결과
- Focus, Selection, Disabled와 Form 동작
- 제품이 제공해야 하는 접근 가능한 이름과 콘텐츠

스타일, Token, Theme과 제품 비즈니스 로직은 Coral에 추가하지 않는다. 실제
필요가 확인되지 않은 옵션이나 변형도 미리 만들지 않는다.

### 3. 구조와 행동을 실제 렌더링 계층에서 완성한다

Coral은 자신이 제공하는 구조, 상태와 접근성 동작을 컴포넌트 계층에서 함께
완성한다. Focus Trap, Focus 복원, 외부 영역 비활성화와 Scroll Lock처럼 DOM
생명주기가 필요한 동작을 실행되지 않는 선언적 계약으로만 제공하지 않는다.

현재 정해지지 않은 렌더러와 공개 패키지 API를 구현 과정에서 임의로 확정하지
않는다. 특히 제거한 Bison의 Machine·Actor·Connect·Normalizer와 Framework
Adapter 구조를 이름만 바꾸어 복원하지 않는다.

### 4. `render`는 네이티브 Tag의 계약에 따라 제공한다

`render`를 모든 Part에 기본으로 제공하지 않는다. Part의 의미, 키보드와 Focus,
Form 참여, Disabled 전파 또는 요소 사이의 구조적 관계를 네이티브 Tag가 소유하면,
다른 요소로 교체했을 때 Coral이 같은 계약을 보장할 수 없으므로 `render`를
제공하지 않는다.

네이티브 Tag와 독립적으로 Coral이 Props, Event와 ARIA를 통해 계약을 보존할 수
있고 실제 합성 요구가 확인된 Part에만 `render`를 추가한다. 현재 닫힌 `render`는
구체적인 필요와 대체 요소가 지켜야 할 접근성 계약이 정해졌을 때 이후에 열 수
있다. API의 일관성이나 예상한 확장 가능성만으로 미리 제공하지 않는다.

### 5. 사용자가 경험하는 결과를 검증한다

공개적으로 지원하는 모든 동작은 실제 렌더링 결과를 기준으로 테스트한다.

- 모든 컴포넌트에 Type Test를 기본으로 작성하지 않는다. 네이티브 Props, Ref와
  Event 타입을 그대로 재노출하거나 공개 선언을 반복하는 테스트는 두지 않는다.
- Props 조합에 따른 타입 변화, Generic 추론이나 잘못된 사용의 거부처럼
  TypeScript만 표현할 수 있는 비자명한 공개 계약이 있을 때만 Type Test를
  추가한다.
- HTML 구조, Role, accessible name과 ID 참조 관계를 검증한다.
- 키보드와 Focus 동작은 실제 브라우저에서 사용자 입력으로 검증한다.
- 네이티브 HTML이 전적으로 소유하는 동작을 Coral 코드의 동작처럼 중복
  테스트하지 않는다. 테스트를 두지 않는 이유와 경계는 해당 테스트에 남긴다.
- 조건부 ARIA 속성은 필요한 조건과 필요하지 않은 조건을 모두 검증한다.
- Focus Trap, Focus 복원과 외부 비활성화는 선언값이 아니라 실제 DOM 결과를
  검증한다.
- 버그를 수정할 때는 재발을 막는 테스트를 추가한다.

스타일이나 특정 제품의 표현은 Coral의 테스트 조건으로 사용하지 않는다.
